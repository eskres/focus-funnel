## Why

Filing a thought today means opening the chat, starting or picking a conversation, and typing `/push`. On a phone, a thought usually starts somewhere else: a link in the browser, a line in a message. The user needs to send text straight to proposal cards, from a small box or from the phone's share sheet, without a conversation in the way. The confirm-to-save rule stays: nothing is stored as a thought until the user confirms a card.

## What Changes

- A new Capture page at `/capture`, laid out for a phone. It holds one text box and a "Make cards" button. It is reached from a sidebar link "Capture" beside "Upcoming" and "Library", and from a shortcut of the installed app.
- "Make cards" runs the text the way `/push` runs it: one turn on the user's default model and effort, with the proposal tool forced, the similar-thought check and refs, dates in the browser's time zone, and status marks. A capture never picks a model for the user: with no default model it is refused with `model_not_set`.
- Each capture is a conversation of its own that the sidebar does not list. Its cards show on the Capture page, under the box, and are confirmed there with the same card as in the chat. Nothing is stored as a thought until a card is confirmed. A saved thought's origin is that capture, shown as any origin, with the start of the captured text as its title.
- The Capture page lists the captures that still wait, newest first: one that is still making cards, one with a card not yet confirmed, and one that ended with no cards, with the reason. A capture leaves the list once every card is confirmed and a thought saved or added to from it still exists; a capture whose confirmed cards only marked tasks done stays until dismissed, and one whose saved thoughts are all deleted comes back. The user can dismiss a waiting capture: one that no saved thought links to is deleted, and one with a saved thought is closed, so its saved thoughts keep their origin and its unconfirmed cards stay in its conversation. The dialog says which. "Try again" is offered on a capture that failed with no cards. A capture whose turn was stopped is not shown as failed. A capture whose every card is confirmed, or that was carried on as a conversation, cannot be dismissed from the Capture page.
- A capture is checked before any model call: empty text, text over 20,000 characters, no default model, the monthly spend cap (`spend_cap_reached`, from `stop-and-spend-cap`), and a text too long for the default model's context (`context_full`, with a message for the Capture page) each refuse it with the shared error shape, and nothing is stored. The box keeps the text.
- Sending a chat message in a capture's conversation, opened from a thought's origin, makes it an ordinary conversation, listed in the sidebar. A resent message does too. `/compact`, and a message refused because an answer is running, leave it a capture.
- Deleting a thought sets a closed capture back to waiting when no other thought links to it, so its text is never stored where no page reaches it.
- New endpoints `POST /api/captures` (starts a capture, answers `202` once the turn runs), `GET /api/captures` (the waiting captures with their cards, or only the ones asked for by `ids`, which the page uses while a capture runs), and `DELETE /api/captures/{id}` (dismisses a waiting capture). All are owner-scoped. Confirm uses the existing conversation route.
- A capture runs with no one watching, so it does not use up the month's usage warning: the notice comes with the next chat answer.
- The app becomes installable: a web app manifest with icons, `start_url` `/app`, and a share target. The share target is a `GET` to a new `/share` page with `title`, `text`, and `url`. That page moves the shared text into the browser's storage, takes it out of its address, and opens the Capture page with the text in the box. It calls no model; the user taps "Make cards". Before the user presses "Make cards", the text reaches the app's server only in that one request line, which is marked `no-store` and `no-referrer` and is not logged. The frontend server accepts request lines up to 256 KB, so a long share fits. The text kept in the browser's storage is removed at every logout and never fills another user's box. The browser's history keeps the `/share` address, as it does for any visited page.
- A share that arrives logged out comes back to the Capture page with the text after login, in every login mode.
- A service worker at `/sw.js`, scope `/`, that caches nothing and serves nothing itself. Offline use is not part of this change.
- The manifest, the service worker, and the icons need no login. In demo mode they are marked `no-store` and start no demo session.
- Demo mode works the same: the demo notice comes before the first capture, held keys are used for it, and captures are deleted with the session.

## Capabilities

### New Capabilities

- `quick-capture`: the Capture page and its box, how a capture becomes proposal cards on the user's default model, the cards and the waiting list on the page, dismissing, the checks before any model call (including the spend cap), demo mode, and owner scoping.
- `installable-app`: the web app manifest, the share target and the `/share` page, coming back to a share after login, the service worker and what it caches, and which of these files need no login.

### Modified Capabilities

- `conversations`: "The sidebar lists conversations" leaves out capture conversations, and a message sent in one, other than `/compact` or one refused as busy, makes it an ordinary conversation.
- `context-management`: "A message that cannot fit is refused" (as `mcp-connectors` leaves it) also covers a capture too long for the default model, which stores nothing and gets its own advice.

## Impact

- Backend: `app/models/conversation.py` and one Alembic migration (`conversations.capture_state`, a check constraint, and a partial index); a new `app/routers/captures.py` (`POST`, `GET`, and `DELETE /api/captures`); `app/routers/chat.py` (the turn start shared with captures, and a message in a capture conversation clears `capture_state`); `app/chat/turn.py` (a `warn` flag that skips the usage warning); `app/routers/conversations.py` (the list leaves out captures; confirm closes a linked capture whose every part is confirmed, with a conditional update; the stop and claim steps shared with the capture delete); `app/thoughts/store.py` (`delete_thought()` sets a closed capture it leaves unlinked back to `open`).
- Frontend: a new `app/capture/` (layout and page) and `components/capture/`; a new `app/share/page.tsx`; a new `app/manifest.ts`; new `public/sw.js` and `public/icons/` (committed PNGs, no script); a new `components/pwa/service-worker.tsx` mounted in `app/layout.tsx`; a new `lib/captures.ts`; `lib/api.ts` (`storedError()`); `components/chat/chat-error.tsx` (`showRetry` and `title`); `components/chat/delete-dialog.tsx` (`confirmLabel`); `lib/account.ts` (`logOut()` removes the kept shared text), a new `components/logout-button.tsx` that calls it in place of the four logout links, and `components/demo/demo-bar.tsx` (removes the kept shared text); `Dockerfile` and `package.json` (`NODE_OPTIONS=--max-http-header-size=262144`); `proxy.ts` (public PWA files, and `/share` with its headers); `components/chat/sidebar.tsx` (the "Capture" link).
- Docs: `docs/login.md`'s section "HTTPS on your network" says not to log query strings and that the reverse proxy must allow long request lines.
- API: new `POST /api/captures`, `GET /api/captures`, and `DELETE /api/captures/{id}`. `GET /api/conversations` no longer lists capture conversations. No breaking change for the chat.
- Dependencies: `@playwright/test` as a frontend dev dependency, for the checks in `frontend/e2e/`, which run against a running app and are not part of `npm test`.
- Cost on the user's key: one capture costs what the same `/push` costs. Listing the waiting captures makes no provider call.
- Depends on `background-turns` (the turn runs without a request), `stop-and-spend-cap` (the cap check, and a delete stops a running turn first), `thought-dates` (the request zone), `thought-appending` and `thought-status` (the parts a `/push` can make, and the card that shows them), `thought-editing` (built: the card's saved and deleted state, the sheet), `thought-library` (the sidebar links), and `mcp-connectors` (its context-management text, which this change modifies). None of them but `thought-editing` is built on this branch; this change is planned against their specs and designs.
