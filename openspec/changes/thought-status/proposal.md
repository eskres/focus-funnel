## Why

A filed `task` can never be closed. No thought has a status today, so "call the plumber" stays a to-do forever, and a question about open tasks gets back the ones already done. A thought needs an open or done status that the user sets, from the chat or from the sheet.

## What Changes

- Every thought has a status: `open` or `done`. A new thought is `open`. Existing thoughts become `open`. The time of the last status change is kept.
- A status change touches nothing else. It does not change the thought's title, summary, tags, category, raw text, or "changed" date, and it makes no embedding call. So it does not count as a change to the thought when an addition proposed before it is confirmed, or when the last addition is undone, and neither of those changes the status.
- `propose_thought` gains an optional `marks` list beside `thoughts`; a call with only `marks` may leave `thoughts` out, and two marks with the same ref count as one. Each mark names a thought the conversation has seen by its ref (`T1`, `T2`, … from the `thought-appending` change), to mark it done. "I called the plumber" makes the model propose marking that task done. A mark is written as one more part of the same proposal as any new thought or addition, so one answer still shows one proposal. The new-thought part schema does not change.
- When the task is not among the thoughts the conversation has seen, the model first searches the user's open thoughts for it, before any proposal in the turn, then makes one proposal with the mark and anything new. With a held proposal, the one proposal holds the held parts and the mark, whether the task was seen or not. When several open thoughts match, the model marks the most recently filed one and names the older ones in its reply. When the finished thing is a held card that was never confirmed, the model proposes nothing for it and says the card can be passed over. With `/push`, whose first call must be a proposal, a finished task proposed as a new note is caught by the similar-thought check, and the model marks the task it lists instead; `thought-appending`'s line "A repeated task is usually a new task." gains "unless the user says they finished it". A turn gets four model calls instead of three, so this fits. A mark that also carries a summary or a date is refused, so neither is lost. A mark that cannot apply sends the call back to the model with one line per bad mark, and asks it to send the call's other parts again.
- The card for a status part says "Mark done: <title>", and a screen reader names it so. Nothing changes until the user confirms it. A confirmed card says "Marked done: <title>" with a link. A confirm of a thought that was deleted says it no longer exists; any other failed confirm shows the reason and keeps the button. Reopening is done in the sheet, not from the chat.
- A confirmed status part does not count as a filed thought: the discussion before it is still offered before `/compact` and archive. A status part never keeps a proposal held: an unconfirmed mark is not offered again on a change of topic, at archive, or at `/compact`, and a later proposal does not fold its card away, so it stays confirmable in the chat. The offer before archive and `/compact` holds no marks and ignores any the model sends, in both of its asked calls, and it does not file a finished task as a new thought.
- The thought detail sheet gets a Done toggle. It saves at once, and the sheet shows when the thought was marked done. It also sets a done thought back to open.
- `PATCH /api/thoughts/{id}` takes `status`; `GET` answers `status` and `status_changed_at`.
- `search_thoughts` takes two optional filters: `status` and `category`. The search tool offers only `status: open`. "What tasks are still open?" searches with `status: open` and `category: task`, and leaves out done ones. With either filter, the query is optional. Without a status filter, search still finds done thoughts, and the result marks each done one.
- The note of seen thoughts and the list of similar thoughts tell the model which thoughts are done. The chat's tool summaries name a status proposal, a refused mark, and a search with no query in their own words, and are stored, so a reload shows the same words.
- The Upcoming page (from `thought-dates`) lists only open thoughts.
- `archived` is not a status in this change. A later change that adds archiving adds it as a third value of the same status. Every "open" list here asks for `open` by name, so an archived thought drops out of it with no change (design decision 2).

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `thought-store`: new requirements: every thought has an open or done status, and a status change leaves the rest of the thought and its search entries alone.
- `thought-filing`: new requirements: a proposal part can mark a filed thought done, which is applied only when the user confirms it; such a part does not count as filing; a status change does not block confirming or undoing an addition. Modified requirements "A message with several thoughts is split": merging is not offered, and a merge confirm is refused, when a part marks a thought done, and only parts that file or add keep the raw text; "Confirming a proposal saves it": confirming a status card stores no thought; and "Similar filed thoughts are checked" (from `thought-appending`): a new part whose candidate the user says they finished is dropped, and the candidate is marked done.
- `conversation-agent`: new requirements: the model proposes marking a thought done by ref, searches open thoughts first when the thought is not seen, marks only the newest of several open matches, makes one proposal with a held proposal and a mark whether the thought was seen or not, leaves out a held part the user says is finished, refuses a mark that carries a date, is told every mark that cannot apply and to resend the call's other parts, does not say it was done before the user confirms, marks a finished task that the similar-thought check lists instead of filing it again (also after `/push`, with the repeated-task line qualified), and is told which thoughts are done, in search results, the seen-thoughts note, and the similar-thought question; the search tool filters by the status `open` and by category. Modified requirements "A proposal is held while the conversation carries on": a status part does not keep a proposal held, is not offered again, and is not folded away; "Tools to file and find thoughts" (from `thought-appending`, to be merged with `mcp-connectors`' version before archive): only a proposal after a candidate round skips the similar-thought check, and a refused call does not count; and "The offer before an action may propose nothing" (from `thought-appending`): a proposal whose only confirmed parts marked thoughts done is not a saved proposal, so the model is still asked.
- `thought-search`: modified requirement "Filters and order": search filters by status and by category, and needs no query with either; a search with no query lists and counts only the user's own thoughts.
- `chat-interface`: new requirements: the status-change card, its accessible name, a failed confirm, its state after a reload (never merged with an addition to the same thought), and its state when the thought is deleted after the mark. Modified requirement "A proposal can be reviewed in the chat" (from `thought-dates`): a status card is not edited and offers no merge, and the scenarios on holding, editing after a reload, and merging speak of new thoughts.
- `thought-detail-view`: new requirement: the sheet's Done toggle. Modified requirement "A thought opens in a side sheet": the sheet shows whether the thought is done and when, and Done joins Edit, Delete, and `thought-appending`'s Undo as a way the sheet changes the thought.
- `upcoming-thoughts` (added by `thought-dates`): modified requirement "The Upcoming page lists dated thoughts from today on": it lists only open dated thoughts.

## Impact

- Backend: `app/models/thought.py` and one Alembic migration (two columns); `app/thoughts/store.py` (`set_status()`); `app/routers/thoughts.py` (`status` in `GET` and `PATCH`, Upcoming filter); `app/thoughts/search.py` (status and category filters, a list with no query); `app/chat/prompt.py` and `app/chat/tools.py` (marks, the propose tool with no marks for the offer, search filters, notes including the finished-task lines in `HELD_PROPOSAL_NOTE`, the qualified repeated-task line of the candidate round, and the finished-task line in `OFFER_NOTE`, result marks, `PROPOSAL_SHOWN_STATUS`, `ToolRefusal`); `app/chat/turn.py` (refusals passed through as they are, the held note dropped only after a proposal row is written, the tool summaries, stored as `details.summary`); `app/chat/proposal.py` and `app/routers/conversations.py` (marks in the payload, the offer, and confirm; what counts as filed and as held; marks ignored in both asked calls of the offer, before any check; done markers on similar-thought candidates, in a turn and in the offer); `app/chat/chat.yaml` (`tool_rounds: 4`).
- Frontend: `lib/thoughts.ts` and `lib/sse.ts` (types), `components/chat/thought-sheet.tsx` (Done toggle), `components/chat/proposal-card.tsx` (status card; status cards of a replaced proposal not folded away; a group with a mark never read as merged; the card's and the group's names; a failed confirm that keeps the button), `components/chat/chat.tsx` (stored tool summaries on reload), `components/chat/proposal-dialog.tsx` (status parts left out of the offer dialog).
- API: `status` and `status_changed_at` on `GET /api/thoughts/{id}`; `status` on `PATCH`; `mark` on proposal parts.
- Cost: none on the user's key for a status change. A search with only status or category filters makes no embedding call, and a call with only marks makes no similar-thought check. "I called the plumber" for a thought the conversation has not seen costs one search round. The fourth call per turn is used only by a turn that needs it, or by a model that loops.
- Depends on `thought-editing` (built on this branch: `PATCH`, `saved_title`), `thought-appending` (planned: refs, the seen-thoughts note, `target` on proposal parts, the similar-thought check), and `thought-dates` (planned: the optional search query, "Filters and order", the Upcoming page). Archive after all three and after `mcp-connectors` (design decision 15); `thought-dates`' card requirement is itself a copy of `thought-editing`'s.
- Overlaps `mcp-connectors` (planned) in `_run_tool()`'s propose branch and error handling; whichever is built second moves this change's refusal pass-through and result texts into its `BuiltinTools` (design Risks). Both modify `conversation-agent` "Tools to file and find thoughts"; this change merges `mcp-connectors`' text into its copy before archive.
